# Согласованные визуальные и UX-решения

Комплект принят пользователем 20 октября 2026 года после трёх редакций. Это ориентир для реализации по [Issue № 37](https://github.com/SergeyMotynga/daily_organizer/issues/37). Изображения в [exports/](exports/) и общая [сетка](mockup.html) должны использоваться вместе с существующей функциональной спецификацией; API и бизнес-правила этим документом не изменяются.

## Общая система

Холст 1920 × 1080. Верхняя горизонтальная навигация: «Сегодня», «Задачи», «Календарь», «Проекты», «Архив». Поля, размеры и содержание двух тем одинаковы. Светлая палитра тёплая и зелёная, тёмная — графит и лайм. Значения извлечены из CSS в [tokens.json](tokens.json).

| Роль | Светлая | Тёмная |
|---|---|---|
| Фон | `#f7f6f2` | `#1c211f` |
| Панель | `#fdfdfc` | `#242a27` |
| Контекст | `#f2f2eb` | `#252c27` |
| Текст | `#101b23` | `#f3f5ef` |
| Второстепенный текст | `#59626a` | `#bdc6bf` |
| Акцент | `#18593f` | `#d4ed86` |
| Выделение | `#e8efe6` | `#303d31` |
| Дедлайн | `#a95000` | `#ffb141` |
| Истёкший дедлайн / ошибка | `#bb3036` | `#ff7d7f` |

Шрифт — Segoe UI, затем Arial/sans-serif. Базовый размер 20 px, заголовок страницы 38 px, обычная задача 23 px, задача списка 21 px. Высота шапки 76 px, горизонтальный отступ страницы 28 px, правая колонка 482 px, промежуток панелей 20 px. У панели радиус 20 px. Конкретные размеры форм, таблиц и малых элементов заданы в CSS. Системный шрифт может немного отличаться между ОС; JPG фиксируют согласованный вид.

Логотип «Маршрут» используется без изменения пропорций. Знак и версии с названием для двух тем сохранены в [references/](references/). В шапке приложения название может оставаться обычным текстом рядом со знаком. Daily Organizer пока рабочее название.

## Сценарии

| Область | Принятое решение |
|---|---|
| Сегодня | Компактные строки, правая колонка контекста, раскрытие деталей внутри списка. Неочевидное поле «Что нужно сделать?» удалено; создание через «Новую задачу». |
| Задачи | Вкладки «Активные / Выполненные / Все». «Все» объединяет оба статуса, архив остаётся отдельно. Дублирующие чекбоксы статуса справа удалены. |
| Старые задачи | Группа «Ранее» с точной плановой датой. Пропущенный план и истёкший дедлайн обозначены отдельно; автоматический перенос на сегодня не предполагается. |
| Фильтры | Постоянный календарь сохранён по прямому уточнению пользователя. День или период выбираются в нём; отдельного выпадающего списка плановых дат нет. Обе картинки используют одну и ту же панель. |
| Выбор периода | Переключатель «День / Период», выделенные границы и середина периода, выбранное значение и действия под календарём. Применённый период в списке показан одной строкой со сбросом. |
| Календарь | Неделя и месяц, контекст выбранного дня, план отдельно от дедлайна. Без выдуманных длительностей задач. Элементы панели управления имеют общую высоту 50 px и текст 18 px; стрелки 50 × 50 px. |
| Проекты | Активные и архивные проекты, поиск, прогресс. Нижняя поясняющая строка расположена у нижнего края страницы на одной высоте. |
| Доска и список | Пять стандартных этапов. В списке — выделение, массовый перенос и выполнение; частичное общее выделение показано минусом. |
| Длинные списки | Прокрутка строк внутри панели, заголовок и пагинация остаются отдельно; счётчики соответствуют демонстрационным данным. |
| Формы задач | Единая компактная сетка. Плановая дата/время и дедлайн стоят рядом; быстрые даты и лишние пустоты удалены. Повторение раскрывает интервал и границы правила. |
| Новый проект | Названия этапов можно редактировать и добавлять свои. У каждой строки явный флажок «Завершающий»; в макете отмечен «Готово». Ограничение: в проекте должен оставаться завершающий этап. |
| Настройки проекта | Основные поля слева, этапы справа, архив/удаление с пояснением последствий. Удаление заполненных и завершающего этапов недоступно. |
| Архив | Подсказка включена в подзаголовок, отдельная пустая строка над таблицей убрана. |
| Вход и регистрация | Приняты пользователем, сохранены после дальнейших правок остальных экранов. |
| Общие состояния | Пустой результат, загрузка, ошибка, валидация, подтверждение и уведомление — отдельный служебный справочник, не страница приложения. |

Данные на изображениях вымышлены. Календарь и Today показывают один набор задач выбранного дня. Редактор повторений иллюстрирует изменение правила английского на каждые две недели до сохранения, поэтому текущие повторы календаря не меняются.

## Граница реализации и Notion

Согласовано визуальное расположение управления этапами при создании проекта. Последовательность создания проекта и сохранения этапов, смена завершающего этапа, ограничения повторений и завершения должны соблюдать действующую модель. Вводить новые API-контракты или менять допустимое число завершающих этапов только по виду флажков нельзя.

Перед реализацией нужно перенести в актуальные UX-требования Notion: верхнюю навигацию, две темы и параметры сетки, раскрытие задач, вкладки статуса, группу «Ранее», постоянный календарь с периодом, формы и управление этапами. [Существующий UX-черновик](https://app.notion.com/p/3fe678c73f4781df8599e58df97ed940) остаётся связанным материалом. В этом PR Notion не редактировался. Мобильные варианты и дальнейшие улучшения продуктовой логики требуют отдельной задачи.
