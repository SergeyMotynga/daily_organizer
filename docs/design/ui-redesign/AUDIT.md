Задача: [#36](https://github.com/SergeyMotynga/daily_organizer/issues/36). Проверка выполнена на уже запущенном пользователем `http://localhost:5173` 19 октября 2026 года. Код приложения, API, схема БД и настройки запуска не менялись. Серверы приложения не перезапускались.

Результат — предложение интерфейса для согласования. Это не реализация #37 и не приёмочное тестирование #38.

| Форма | Сохранённые поля и действия | Подтверждение | Макет |
|---|---|---|---|
| Новая задача | Название до 255 символов, описание, проект или «Без проекта», этап; статус обычной задачи; плановая дата/время; дедлайн дата/время; повторение; отмена/создание | [Форма](evidence/16-create-task.png), [mobile](evidence/39-mobile-task-form.png) | `task-create`, `task-no-project`, `task-invalid` |
| Повторение | Не повторять / каждый день / по будням / каждую неделю; интервал по дням или неделям; начало и необязательное окончание | [Поля](evidence/17-create-recurring-task.png), просмотрены три режима в UI | `task-recurring`, `task-recurrence-options` |
| Редактирование задачи | Те же поля с существующими значениями, удаление, отмена и сохранение | [Редактирование](evidence/22-task-edit.png) | `task-edit` |
| Детали | Описание, статус, проект/этап, план, дедлайн, повторение, создано/обновлено/архивировано; редактирование, выполнение/возврат, архив/восстановление, удаление | [Детали](evidence/21-task-details.png), [выполнено сегодня](evidence/32-occurrence-completed.png) | `task-details`, `task-occurrence`, `states` |
| Создание проекта | Название до 255 символов, описание, пять стандартных колонок | [Создание](evidence/12-create-project.png) | `project-create` |
| Настройки проекта | Название, описание; переименование/добавление/порядок колонок; завершающая колонка; архив/восстановление; удаление с сохранением задач без проекта | [Настройки](evidence/14-project-settings.png), [удаление](evidence/15-project-delete-confirm.png), [архив](evidence/34-archived-project-settings.png) | `project-settings`, `project-settings-confirm`, `project-column-edit` |
| Выбор даты | Предыдущий/следующий месяц, месяц и год, день, сегодня, очистка и закрытие; диапазон для фильтра | [Дата](evidence/09-date-picker.png), [период](evidence/27-date-range-filter.png) | `planning-filter`, `controls` |

План и дедлайн независимы. Время имеет смысл вместе с соответствующей датой. Предупреждение «план позже дедлайна» не запрещает сохранение само по себе. Повторение не закрывает всё правило навсегда: выполнение относится к дате. Для `weekdays` нет редактируемого интервала. Без проекта выбор этапа отключён; повторяющуюся задачу нельзя поместить в завершающую колонку. Завершающая колонка одна, её удаление недоступно.

Регистрация: пароль 8–30 символов, только латинские буквы и цифры; обязательны обе группы; без пробелов; повтор должен совпадать. Новые макеты не добавляют восстановление пароля, email, SSO или другие отсутствующие auth-экраны. Backend-возможность без доступного web-экрана не выдаётся за существующую страницу.

## Наблюдения для нового UI

| Наблюдение | Предложение |
|---|---|
| Крупные summary-карточки отнимают высоту Today, даты и действия разбросаны по широкой строке | Краткая сводка в заголовке списка; компактный контекст справа; детали раскрываются внутри строки |
| Время плана, дедлайн и исторические даты легко спутать | Подписывать назначение даты. Янтарный — дедлайн, коралловый — просрочка; план и обновление остаются нейтральными |
| В выбранном дне календаря 21 октября повторение видно и в «Без времени», и в «Повторения» | Одна запись на occurrence в выбранном дне, с иконкой и подписью повторения. План и дедлайн одной задачи могут отображаться отдельно |
| При открытии будущего повторения детали всё равно предлагают «Выполнить сегодня» | Сохранять явный контекст сегодняшнего выполнения; произвольное выполнение будущего дня не вводить молча |
| Заголовок недели отображается как «19–25 октябрь» | В макете «19–25 октября» |
| На auth-экране указан v0.1, в shell — v0.2 | В новой навигации нет версии продукта как постоянного визуального акцента |
| Таблицы и широкая доска требуют особого поведения на телефоне | Табличные строки становятся карточками с теми же свойствами; доска сохраняет горизонтальное перемещение между этапами |

Это UX-наблюдения, а не исправленные баги. Код под них в этой задаче не менялся.

## Проверено и не проверено

- Просмотрены все доступные маршруты web-приложения, пустые и заполненные разделы, общие формы, меню и подтверждения; desktop и ширина 390 px.
- Снимки 02–49 сохранены в `evidence/` — 48 файлов. Снимок входа с исходным браузерным автозаполнением исключён из Git. QA-пароль отсутствует в артефактах.
- Проверены создание и редактирование, статусы, перенос этапа через массовые действия, архив/восстановление, выполнение повторения сегодня и auth-сценарии. Это исследовательский проход, не полный регресс.
- Настройка времени через автоматизацию нативного поля `time` не дала подтверждённого сохранённого значения. Наличие полей и их назначение подтверждены UI и исходниками; ввод/сохранение времени и часовые пояса нужно отдельно перепроверить в #38. В макетах время — иллюстративные данные.
- Drag handle доски и управление порядком колонок просмотрены; сам перенос задачи выполнен через массовое действие. Полную drag-and-drop проверку оставить #38.
- Ошибку неверного пароля и валидацию регистрации воспроизвели. Сетевой сбой/недоступность backend специально не вызывали. Загрузка, сетевые ошибки, pending и success на листе `states` — проектные состояния, а не утверждение о воспроизведённых отказах.
- Граф использован для навигации. Широкий запрос был усечён, часть связей устарела относительно frontend; выводы сверены с текущими исходниками и UI. Новые артефакты не представлены как уже проиндексированные графом.
