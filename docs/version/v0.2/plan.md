# Daily Organizer v0.2: черновой план

`v0.2` начинается после функционального закрытия `v0.1` с app structure refactor.

Главное правило: не превращать `v0.2` в бесконечный релиз. Лучше выбрать один продуктовый фокус и довести его до состояния "можно пользоваться".

## Первый этап: app structure refactor

До добавления новых продуктовых сущностей общий app shell нужно отделить от task module:

- основные маршруты задач переносятся под `/app/tasks/*`;
- task navigation оформляется отдельной группой «Задачи»;
- старые маршруты `/app/today`, `/app/planning`, `/app/calendar` и `/app/archive` сохраняются как redirects;
- пустые разделы будущих модулей пока не показываются в UI;
- frontend menu structure должна позволять позже добавить группы «Заметки», «Проекты», «Финансы» и «Отчёты».

Этот этап не меняет backend, API и бизнес-логику задач.

## Выбранный продуктовый фокус: личные проекты

После app structure refactor в `v0.2` добавляется модуль личных проектов:

- один пользователь владеет своими проектами;
- совместная работа, участники, приглашения, исполнители и комментарии пока не входят в scope;
- проект содержит настраиваемые колонки Kanban-доски;
- существующая сущность задачи используется и для личных, и для проектных задач;
- задача без проекта остается обычной todo-задачей;
- проектная задача продолжает отображаться в Today, Planning и Calendar согласно своим датам;
- проект предоставляет представления «Доска» и «Список»;
- перенос в завершающую колонку синхронизируется со статусом `done`;
- drag-and-drop реализуется через `@dnd-kit/react` и `@dnd-kit/helpers`, а UI остается собственным.

Desktop-референсы лежат в `docs/reference/v0.2/projects/`.

Порядок реализации:

1. Завершить app structure refactor.
2. Добавить backend-модель проектов и колонок.
3. Добавить экран «Все проекты» и создание проекта.
4. Добавить Kanban- и list-представления проекта.
5. Связать проектные задачи с существующими task views.
6. Добавить настройки проекта и колонок.

## Отложенные направления

### Вариант A. Notes / быстрые мысли

Изначальный roadmap предполагал, что `v0.2` добавит заметки и быстрые мысли.

Смысл:

- быстро записать мысль без превращения в задачу;
- хранить короткие заметки отдельно от todo;
- позже связывать заметки с задачами, проектами и AI/MCP.

Минимальный scope:

- CRUD заметок;
- список заметок;
- поиск;
- простые теги или без тегов на первом шаге;
- отдельный раздел в app shell;
- адаптивный UI в стиле v0.1.

### Вариант B. Product hardening

Если хочется сначала сделать `v0.1` надежнее перед новыми сущностями:

- визуальный QA pass;
- e2e-сценарии;
- accessibility-проверка;
- performance/code splitting;
- чистка frontend-компонентов после UI rebuild;
- стабилизация календаря и date filters.

### Вариант C. Deploy / infrastructure

Если цель - начать пользоваться приложением с разных устройств:

- Docker production build;
- CI checks;
- VPS;
- reverse proxy;
- HTTPS;
- домен;
- backup PostgreSQL;
- секреты и env configuration.

## Следующий шаг после v0.2

Notes, hardening и deploy остаются кандидатами для следующей версии после завершения личных проектов.

## Что не стоит делать в v0.2

- Не добавлять AI/MCP раньше стабильных пользовательских сценариев.
- Не смешивать notes, deploy, finance и reports в одном PR.
- Не переписывать backend-архитектуру без конкретной боли.
- Не начинать нативное mobile app до стабильного web MVP.
